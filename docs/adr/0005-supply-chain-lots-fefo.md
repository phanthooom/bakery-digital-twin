# ADR-0005: Цепочка поставок — партии, списание по рецептуре и FEFO, события вместо остатков

Статус: принято, 2026-10-08

## Контекст

Двойник показывает весь путь: сырьё приходит → из него готовят → упаковывают → хранят → отгружают и доставляют. Для пищевого производства нужна прослеживаемость (какая мука в какой партии хлеба и у какого клиента) и контроль сроков годности.

## Решение

- Учёт ведётся **партиями**: у каждой — остаток, дата, срок годности, источник (поставщик или смена с входными партиями сырья).
- Выпуск списывает сырьё **по рецептуре**; и сырьё, и продукция уходят по **FEFO** (первой — партия с ближайшим сроком). Не хватило сырья — выпускается столько, на сколько хватило, и нехватка записывается.
- Отгружается только **упакованная** и не просроченная продукция; просрочка списывается в потери.
- Состояние склада — результат **проигрывания событий** (приход, выпуск, упаковка, отгрузка, списание) в `Inventory`. Демо-источник генерирует события детерминированно; живой будет получать их из учётной системы — модель и интерфейс те же.

## Последствия

- Остаток не «вводится руками», а следует из событий; расхождение с фактом видно как нехватка при выпуске/отгрузке — повод для инвентаризации.
- Прослеживаемость в обе стороны бесплатна: связи хранятся в партиях.
- Проигрывание всего периода дёшево (сотни событий в сутки); для лет истории понадобится снимок остатков на дату + события после него.
